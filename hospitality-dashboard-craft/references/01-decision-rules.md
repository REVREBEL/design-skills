# Decision doctrine
**Invariants** depend on correctness and demonstrable constraints: secure scoped access; provenance and meaning of data; honest test status; mathematical validity and invalid-denominator states; clearly labeled illustrative examples; and applicable WCAG success criteria. Guardrails do not depend on a visual moodboard.

**Context-dependent choices** include top-row KPIs, layout rhythm, table density, touch targets beyond accessibility minima, light/dark preference, visualization type, sticky controls, complexity of keyboard shortcuts, error behavior and freshness requirements. Evaluate task cadence, role, device, and quality of data before choosing.

**Hypotheses** include "three to five KPI cards", 15-second check-in, 45-second forecast editing, 5-second comprehension, particular color schemes and conversions. Record what will be measured, the baseline, sample population and success criterion before calling them tested.

For every assignment: establish user decisions -> clarify entities and data grain -> choose information hierarchy -> prototype visual model -> define states and interactions -> implement -> test -> document trade-offs. Make the smallest safe change to an existing system.

Avoid automatic inverted-pyramid templates, universal 10-state components, blanket icon-only navigation, forced dark mode and claims that an axe scan proves compliance.
