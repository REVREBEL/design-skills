# Workflow: design workspace architecture
1. Inspect roles, property/portfolio scope, top five real jobs, visit frequency, high-stakes actions, desktop and mobile constraints.
2. Identify monitoring vs diagnosis vs transaction vs administration. Choose overview/workbench/console or hybrid with explicit rationale.
3. Map questions to datasets and measures; do not use KPIs lacking reliable contracts.
4. Draw object navigation model: property, date, segment, source, drillthrough, saved views. Preserve state on return and across authorized deep links.
5. Write screen inventory: shared navigation, filters, principal data region, detail inspector, primary action, audit feedback.
6. Specify each important interaction: user intent, trigger, visible state, data/permission prerequisites, success and recoverable failure.
7. Mock at realistic density with long property names, missing KPIs, >20 columns, several currencies and both keyboard and touch users.
8. Deliver annotated IA, interaction contracts, responsive adaptations, risk register and questions for stakeholder validation.
